# 数据时间与过期提示

- 页面构建时间只代表部署，不用于判断数据新鲜度。
- 记录更新时间来自每场赛事的 updatedAt，表示采集脚本最近成功处理该记录，不等同于人工核验。
- 按现有 schedule 规则应每日检查的赛事超过 36 小时未更新（或时间无效/在未来）时提示待复核；周检、月检、历史赛事不会被套用日检阈值。
- data/update-health.json 从空记录开始，不反推历史成功时间。lastRun 记录成功/失败数与失败场次名；失败率 ≤20% 视为任务跑通并推进 lastSuccessfulRun，超过则保留上次时间，零待查但正常完成也算跑通。20% 取自实测分布：正常批次失败率 6.7%~17.2%，端点不可达的真故障 79%~92%；原判据 failed === 0 下该时间戳只有约两成概率推进，实测一直是 null。页面据此点名失败场次，不再只报数量。
- dry-run 不写文件，limit 抽样不推进全量任务记录。全失败仍以非零状态退出。
- 该文件与赛事数据一起经过 verify-data 再提交发布。网站只能看到最近已发布批次，失败而未发布的最新尝试仍须查看执行机器日志/告警；页面的逐场过期提示不会因此被部署时间刷新。
- 本机脚本和原有更新 workflow 均提交此文件；未改变任何任务启停状态，也不新增邮件通知。

- 心跳读取 main 上的 lastSuccessfulRun。人工数据提交和失败批次不会刷新停更计时。超过 36 小时、时间缺失或无效均触发告警。
